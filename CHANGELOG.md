# Changelog

Every release of Redline, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning](https://semver.org/) in its `0.x` form: until `1.0.0`, a minor bump (`0.2.0`) may break the CLI, the MCP tools or the agent protocol, a patch bump (`0.2.1`) never does.

Add a line under **Unreleased** with every change worth telling (a merged lot, a user-visible fix). `npm run release -- <version>` turns that section into the release. See `docs/releasing.md`.

## [Unreleased]

### Changed

- Web chat and agent rule (comments on demand): "traite les commentaires" written in a page's Conversation tab hands the page's threads to take to the agent, as "Confier à l'agent" signed with the writer's name, through the new `hand_over_comments` tool of conversation sessions; threads taken by a conversation are left alone and listed in the answer. While no agent runs for the project the Conversation tab says to ask "traite les commentaires de <page>" to a Claude Code conversation. The guide tells agent sessions too to ask in the thread, and leave it open, when a comment asks for a new screen or a new rule.
- Comments on demand (first lot): a new comment thread is "À prendre" and goes to nobody while its page is in Conversation mode (the default of every page). Any Claude Code conversation of an account with Écriture takes a page's threads with `pending_comments {pageId}` ("traite les commentaires de Partager") and answers them with `reply_in_thread`, signed "Claude · conversation de <person> · <folder>". A take belongs to the account, so a compacted or resumed conversation finds its threads again. The card shows "À prendre", "Pris par <person>" or "Pris par toi". The page holds, the "Session terminal" pill, the `terminal` queue reason and `release_page` are gone; existing waiting threads become to take.
- A conversation's answer is never lost: `reply_in_thread` adds the answer to any thread of a project the account writes in, even one handed over, taken over or resolved meanwhile (it never reopens a resolved thread or changes a take), and says what happened. Answering a thread to take takes it. Cards show system lines ("Pris par X, puis confié à l'agent par Y", "puis repris par Y", "Résolu par Y"), a resolved thread folds into "Résolu par <person> · <first words>", and replies are indented with Claude's name in the accent colour.
- Comment mode toggle: the canvas header has a "Commentaires · Conversation / Agent" switch (members with Écriture and admins; disabled with the reason for the others). Switching to Agent asks a confirmation that counts the threads (to take leave for the agent, taken ones stay); switching back is immediate and a toast says how many threads waiting for the offline agent are to take again. Other viewers get a live toast and hint line. A thread sent to an offline agent shows "En attente de l'agent (hors ligne)" and `pending_comments {pageId}` can take it. On a phone the toggle moves to the top of the comments panel.
- Comments on demand (conversation tools): `pending_comments` without a page only lists what waits, page by page; with `threadIds` it takes exactly those threads, `takeOver: true` takes over another account's (recorded "repris par", refused while an agent runs the thread); `release_comments` lets go of the account's takes; threads waiting for an offline agent can be taken; a message posted after a take is marked "new since your take"; a reminder line ends the answers of the pages a conversation published or checked out.
- Comments on demand (drafts and À relire): "Plus tard" is now "Brouillon" and drafts are personal: only their author lists, edits, deletes and sends them ("N brouillons, à toi seul"; "Tout envoyer" sends only your own; deleting asks "Supprimer ce brouillon ?"). Once sent, a draft follows the page's mode (to take, or to the agent as one message); a member lowered to Commentaire keeps their drafts and sends them "À relire". An À relire card now says Claude does not see it yet and has "Envoyer à Claude" (no hand-over); a link made "sans relecture" is worded "directement à prendre".
- Comments on demand (thread cards): "Libérer" on a thread taken by your account (it follows the page's mode again) and "Confier à l'agent" on every open thread not already with the agent, in both modes: the agent handles it, later replies go to the agent, and the card keeps "Pris par X, puis confié à l'agent par Y". A thread taken by someone else asks first; if someone takes it while you click, a toast says so with "Voir et confier". Disabled with the reason and a link to the Agents page when no agent runs (`POST /api/threads/:id/hand-over` answers 409). A failed action shows a toast with "Réessayer". New cards: "Agent du projet", "Question de Claude" ("Ta réponse ira à une conversation de <person>"). Card buttons are 32 px (44 px stacked on a phone).
- Comments on demand (accounts and rights): deactivating an account, or lowering a member below Écriture (or removing them from a private project), frees their taken threads and the relaunches waiting for them, with the line "Pris par X, puis libéré : X n'a plus accès"; they follow their page's mode again (a page archived meanwhile keeps the agent work waiting until it is unarchived). The deactivation dialog says "Ses N fils pris sont libérés" and the Share dialog warns of it. A Commentaire member's reply in a thread now follows the thread's handler instead of sending it back to À relire. A link visitor with Écriture reads "Ton commentaire attend qu'un membre de l'équipe le traite avec Claude". Two accounts sharing a name show their e-mail on cards and in tool answers. `reply_in_thread` on a deleted thread says so, and the web chat hand-over is refused for a writer who lost Écriture.
- A "N à prendre" badge next to "N fils" on each page of the project overview and of the page menu, and the project's total in the overview summary. It counts only the threads a conversation can take now, and updates live. The project's page list now carries `openThreadCount` and `toTakeCount` per page.
- Comments on demand (agents screen and Sessions): the Comments tab of `redline` lists the threads to take or taken by page, with "to take" or "taken by <person>" on each comment and "traite les commentaires de <page>" as the hint; the Sessions screen says why a thread waits ("à prendre par une conversation", "pris par <person>", "en attente de l'agent (hors ligne)").
- Comments on demand (reviews): a review of changes belongs to the account that requested it. `review_feedback` returns that account's finished reviews from any of its conversations (after a compaction too) and takes the remark threads for the fetching account; another account's finished review is listed "demandée par <person>" and fetched only by id with `takeOver: true`, which leaves a "repris par" trace; a deactivated requester's review is fetchable by any member with Écriture. The page's comment mode changes nothing about a review.

## [0.3.0] - 2026-11-17

### Changed

- Review mode, visual pass on the pins lot: the numbered frame of a target is kept inside the artboard, pins straddle their element's top-right corner like the mock-up, the shortcut reminder is centred on a tall artboard and clears a fitted one, the pin popover keeps its save error readable, and the pin undo row matches the remark one.
- Review mode: Habillage, Repères and Tweaks are icon buttons (tooltip and accessible name) so the top bar fits at 1440 px. Feedback is called "retours" in the banner, recap counters, confirmations, error and finished screens and `review_feedback`; the step chip stays "Remarque" and the field is "Remarque générale".

### Added

- Review mode: the canvas view of a step can be zoomed and moved: a zoom bar at the bottom right (−, percentage relative to the step's framing, +, "Recadrer"), Cmd + wheel or pinch zooms under the cursor, the wheel or a plain drag pans; each step opens on its own framing.
- Review mode: steps on canvas elements. `request_review` takes `canvasElements` (ids of a page's sticky, title, arrow...), refuses unknown ids with the page's element ids, and a step without an artboard shows the page canvas cropped on them (neighbouring artboards dimmed, elements framed and numbered). Alt + click pins an element, Alt + drag draws a zone in canvas pixels; at fetch they become canvas-element and zone threads.
- Review and Present: a frameless artboard taller than the stage is shown at its real width (capped to the stage width) and the stage scrolls, instead of being shrunk to the stage height. A tag says "Taille réelle" or "Pleine largeur". In review, the stage scrolls to Claude's first target when the step opens and keeps its scroll position; on a grouped step the thumbnail strip no longer shrinks the artboard.
- Review mode: an "Habillage" button in the top bar shows or hides the device frame or browser window around the artboard, as in Present (the same saved choice). Pressed toggles of the red bar (Habillage, Tweaks) are white.
- Review mode: a step can point at precise elements. `request_review` takes optional `targets` (1 to 10 CSS selectors per step); the stage frames each one with a dashed outline numbered in the declared order, on every artboard of a group, before and after. A selector that matches nothing, or a hidden element, is skipped. A "Repères" toggle in the red bar hides or shows the frames, and the choice is kept.

- `reply_in_thread` takes an optional `resolve`: Claude closes the thread with its answer once the comment is handled and it asks nothing back, so review remarks and comments no longer stay open until closed by hand. The person can reopen it.

### Fixed

- Review mode: the Tweaks panel opens over the stage without pushing or shrinking the artboard.

## [0.2.0] - 2026-11-15

### Added

- The agents screen's Comments tab lists, for every installation, the pages whose threads wait for a terminal session (who holds the page, each comment with author, time and target, `o` opens the page in Redline). It reads them through the new read-only `GET /agent-api/terminal-comments`, which never takes a thread.
- `redline doctor` prints the command and agent host versions, the MCP registration, each installation (SemVer, plus a short build hash when two builds share a version, token, reachability) with the command that fixes each problem, skipped folders under `instances/`, and the current folder's link. It also works before `redline migrate`.
- The server has an instance name (`REDLINE_INSTANCE_NAME`, for example "Lumora"): `/api/config` returns it with the version and the build hash, and the Agents page shows "<name> · v<version>" next to its title. The production compose project name is now a setting (`REDLINE_COMPOSE_PROJECT`, default `redline`) so a second copy can run on the same host.
- `redline setup <address> [--name <name>]` creates one installation per Redline instance under the CLI config dir (`instances/<id>/`: its own login and the build its server serves), named after the server, registers the `redline` MCP once, and refuses while the old single login exists. The same address again replaces the token and restarts the agents the old token had stopped. The server answers `GET /agent-api/instance` (name, version, build hash) for the CLI.
- `redline link [<instance>]` links a folder to an instance without a project or an agent. One resolver (nearest link, here or in a parent) tells which installation a folder uses; `redline mcp` now hands over, in the same process, to that installation's own MCP, whose answers and instructions start with "Instance: <name> (<address>, v<version>)". A folder with no link on a computer with several instances, or linked to an address not installed here, gets a `setup_needed` tool telling what to run. A link may name an address with no project.
- The agent host runs each agent with its own installation's code and token (a Lumora agent and a Local agent can run different builds side by side), speaks a host protocol version (the server's `/agent-api/instance` and the installed build tell it), accepts the current and the previous version, and refuses an older installation with a message naming it and both versions. When the global `redline` command changes, the host restarts once no run is in progress on any installation (idle agents wait offline meanwhile, no run is ever cancelled), starts its agents again and says "Host restarted" in their logs. `redline agent --global --instance <name|address>` picks the instance (`--server` stays an alias), and the instance questions of `redline agent` name the instances with their address and version.
- `redline migrate [--now] [--name <address>=<name>]` moves the old single login to one installation per server (token moved, build installed, agents attached by address), waits for runs in progress unless `--now`, stops the agent host and marks its agents "Stopped by redline migrate.", and is idempotent. A server whose name is taken stays in the old login. Until every server is migrated, every command but `migrate`, `doctor` and `help` refuses, bare `redline` prints the migrate message and every MCP tool answers it. The panel's `npx ... setup` command installs the global `redline` command when it is missing or older, and migrates first on an old computer.
- `redline update <instance|address>` installs the server's current build into one installation (a failed install changes nothing), then the agent host restarts every agent of that installation after its current run (never cancelling one); the browser's "Mettre à jour" restarts the installation's other agents the same way. The global `redline` command is refreshed only from a newer build, so updating an older instance never downgrades it. A server too old for the command, or with nothing newer, is said plainly. `redline remove <instance>` removes an installation and its stopped agents, and refuses while one of its agents or a Claude Code session of it runs (the MCP launcher records live sessions per installation); linked folders keep their link and report it as not installed. In Claude Code, only the sessions of an updated installation pause, with a message naming the installation and both versions, and an installation behind its server tells the user to run `redline update <address>`.
- The "Lancer un agent" panel gives one command, `npx -y <server>/cli/redline-cli.tgz setup <server> --token <token>`, a "Lier un dossier" step (`redline link <instance>`), the global agent with `--instance`, a line saying other instances keep their own version and `redline doctor` checks them, and the instance badge. On the Agents page a refused agent's row shows and copies `redline update <address>`, or `npx -y <server>/cli/redline-cli.tgz migrate` with an explanation when the agent was installed before instances (the agent's hello now carries its host protocol, absent before instances); the server's refusal message names the same command.
- Claude declares a review on its own: the Redline guide and the `request_review` and `publish_page` descriptions tell a terminal session to declare a review when it finishes a series of changes, instead of listing the artboards in the chat.
- Review mode: a terminal session declares a review of its changes with `request_review`; members with Écriture open the link, go through the steps (page order, then reading order) in a red review screen, answer OK (cancellable), finish the review, and the conversation reads the result with `review_feedback`.
- Review mode: pages covered by a review show a banner under the canvas header (requested, in progress, finished waiting for fetch, fetched), and review changes reach other members live.
- Review mode: a member can write a remark instead of an OK on a step (saved as they type, editable and deletable with an undo until the review is finished, others' answers shown under "Les autres"); when the conversation fetches the review, each remark becomes a thread on its artboard, taken by that session and answerable with `reply_in_thread`.
- Review mode: `review_feedback` works without an id (the one finished review of the folder's projects is fetched, several are listed, none finished reports the open ones with their progress), any conversation of a member with Écriture can fetch, a second fetch returns the same result marked already fetched, only terminal sessions can call `request_review`, and members without Écriture get a refusal screen.
- Review mode: a review can cover several pages (steps listed by page in the counter menu); a new `request_review` from the same conversation merges into its open review (a redeclared step gets the new question and keeps its remarks), another conversation opens its own review, and a declaration refuses unknown files and artboards of another project.
- Review mode: the recap shows the counts, every remark with its author (edit or delete your own, with an undo), the OKs and the steps not seen in two columns; finishing asks for confirmation when steps were not seen or another member is still in the review; a finished review can be reopened by any member with Écriture until it is fetched, or filed without sending (final, after a confirmation naming the remarks never sent), and `review_feedback` on a filed review answers "classée sans envoi par X le …". A step that turns read-only while a member types keeps their unsaved text with a "Copier" button.
- Review mode: an artboard republished after an answer turns its step to "Modifié depuis ta revue" (tag naming the author of the new version, red progress segment, "Modifié" in the menu); the member checks again with "Revoir et valider" or "Effacer ma remarque et valider", and Claude gets modified OK-only steps as not seen and modified remarks marked "artboard modifié depuis la remarque". A terminal publish now records the folder of its session.
- Review mode: a step can set the tweak values it opens with (shown as "État affiché ... fixé par Claude", the same artboard can be two steps with different values) and ask to open in mobile; the reviewer gets a Desktop / Mobile switch for responsive artboards and the Tweaks panel, and changes made there stay local to the review. The artboard now keeps padding around it on the stage.
- Review mode: a deleted artboard's step shows "Cet artboard n'existe plus" and drops out of the count, a moved artboard keeps its step, steps of an archived page drop out and come back if the page is unarchived before the review is finished, `review_feedback` gives remarks on deleted artboards or archived pages as text without a thread ("artboard supprimé", "page archivée"), a review left with no step and no remark is filed by itself ("plus rien à revoir", its banner goes), and the loading, error, empty and not found screens follow their mock-ups.
- Review mode: an "Avant / Après" switch in the review's top bar compares an artboard with its version before the series (the version Claude gave in `request_review`, else right after the last fetched or filed review, else before the requesting session's first publish of it; a merged review keeps the oldest one); an artboard created in the series shows "Avant" disabled and "Après (nouveau)".
- Review mode: a step can cover a group of artboards sharing one change (`others` and `title` in `request_review`): the example is shown large with the others as clickable thumbnails ("Revenir à l'exemple"), one "OK pour les M", a remark attached to the artboard shown when it was started and citing the others, the whole group back to "Modifié depuis ta revue" (artboard marked, "Revoir et valider les M") when one artboard is republished, and groups spanning several pages listed last under "Sur plusieurs pages".
- Review mode on a phone (under 700 px): the red bar keeps back, REVUE and the counter (with "Terminer la revue" in its menu) and Avant; the step is a bottom sheet with the progress, the question, the details folded, Remarque / OK, and the remark field with Enregistrée, Effacer and Fermer.
- Review mode, after the final review: a group redeclared with another example stays one step; a redeclared step with new texts goes back to "Modifié depuis ta revue"; a second `review_feedback` returns the first result and hands the threads over to another session when the first one is gone; "Avant" only counts the publishes of the declaring terminal session; a failed reload no longer replaces the review on screen; reviews go with their project; a review covers at most 500 artboards.
- A "Présenter" button in the page's top bar plays the page from its first artboard in reading order.
- Bare `redline` opens the agents screen in a terminal (`redline agents` stays an alias); `redline help`, and bare `redline` outside a terminal, print the commands. The screen shows a "This folder" line (`l` links an unlinked folder to an instance), tabs Agents, Instances and Comments with their counts (Tab or 1 2 3), ← → to move the focus between the log and the list, "↑ n more" / "↓ n more" on a long list, each agent's instance before its model and effort and an Instance field, and `?` for the keys and commands. `n` picks the instance first (one too old for the command is dimmed and refused), and an agent stopped by `redline migrate` says so. The Comments tab is a placeholder for now.
- The Instances tab of the agents screen lists the installations, problems first (update available, too old, token refused, unreachable, then up to date), each with its version and state, a "! n" count on the tab and "checking" per installation while its server answers. The left pane is doctor for the selected one (installed and server versions, token, agents, linked folders, Claude Code sessions, what to do); ↑↓ scrolls it when it has the focus. `u` updates and `x` removes the selected installation as `redline update` and `redline remove` do (`x` asks first: y removes, Esc cancels), with their refusals shown in the screen, and `s` closes the screen to run `redline setup` (address and token asked in the terminal).

### Changed

- The page menu of a project with many pages scrolls inside a bounded height, opens on the current page, and keeps "Vue du projet" in view.

### Fixed

- Behind a proxy or an SSO, the page stopped updating live ("Claude is working on this thread" stayed, "Résoudre" seemed to do nothing until a reload): the event stream now pings every 25 s, asks proxies not to buffer it, opens again when it is cut and reloads what the screen shows; resolving or reopening a thread updates the list at once.
- On Linux, a Claude Code crash showed "Claude Code ended without a result." instead of its own error message.
- `GET /agent-api/terminal-comments` only lists the pages of projects the token's account can read.
- A folder link naming an unsafe server address (read from a cloned repo) is treated as no link, and instance names received from a server are cleaned of control characters and cut to 60 characters.
- The panel's `npx ... setup` command no longer stops on "Run redline migrate first" on an old computer: setup goes through the legacy gate when npx launches it, then migrates.
- `redline link` always asks before switching a folder linked to another instance (also one with no project yet), and before linking a subfolder of a linked folder to a different instance.
- A run starting at the instant an idle agent is stopped for a host restart or an installation update is no longer cancelled: the host asks the worker to stop only when idle.
- A server that cannot be migrated (unreachable, token refused) no longer locks the computer: `redline migrate --forget <address>` drops it from the old login, and `redline setup <address>`, typed by hand, completes the migration of an address still in the old login. Migrate's line for such a server cites both.
- Setup's too-old warning says that the installation's agents and its MCP wait for its server to be upgraded.
- When a hand-over to an installation's MCP fails for a reason other than a missing entry point, the error is shown with the installation's name instead of asking for an update.

## [0.1.0] - 2026-11-10

### Added

- Accounts, sign-in and sharing.
- `browser_sign_in` terminal MCP tool: a single-use agent sign-in link for headless test browsers.
- Component instances: one HTML per component, every mock-up follows it.
- Terminal comments: new comment threads wait for the terminal session that last published the page.
- Background agents: agent host in the background, agents screen in the terminal.
- Archive, unarchive and delete projects, design systems and pages; read-only archived pages; blob garbage collection.
- Self-hosting: installable Redline behind an existing SSO, signed actions, one-command setup.
- A project without a design system gets the style Claude designs for it.
- Design systems: live design systems, project style, components, diffusions, tweak grid, artboard strips, gaps.
- Addresses and navigation: artboard addresses, table of contents, play URLs, cross-page links.
- Comments and conversations: hover outline, whole-artboard and canvas-element threads, message context and chips.
- Canvas elements (text, stickies, shapes, arrows, images, links), frames, responsive artboards, canvas overview.
- One folder can serve several projects; `redline init` is gone.
- `rename_project`, `archive_project` and `rename_page` MCP tools.
- Artboard errors and fit-to-content height.

### Changed

- Artboards take a `frame` instead of a `device`.
- Comment pins sit on their element and are found again by name.
- Phone frames start under an iOS status bar tinted with the page's top colour.

### Fixed

- Many open tabs no longer freeze Redline: one live event stream is shared across tabs.
